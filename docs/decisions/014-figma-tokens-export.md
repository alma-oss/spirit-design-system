# Figma Tokens Export

Date: 2026-08-25

Status: accepted

## Context

Spirit design tokens live in Figma as variables and styles. The committed SCSS and TypeScript packages were generated by a Supernova exporter (`exporters/tokens`). That added an intermediary, made values lag behind Figma, and tied generation to a host we are leaving.

Figma’s public REST API still cannot read variables without an Enterprise plan and the `file_variables:read` scope. Style REST endpoints are metadata-only. Plugin APIs can read local variables, styles, bindings, and the remote alias closure.

## Decision

1. Capture a lossless, versioned **SnapshotV1** in a local Figma plugin. The snapshot is Figma-native (not DTCG), ephemeral, and gitignored.
2. A new Node package, `@alma-oss/spirit-figma-tokens-exporter` (`exporters/figma-tokens`), validates the snapshot, maps it through a strict naming/scoping contract, and generates `packages/design-tokens/src/`.
3. Extraction is a boundary: `extractSnapshot()` today reads plugin JSON. A later Enterprise REST extractor must emit the same SnapshotV1. REST is not implemented now.
4. Output must match the existing file tree, names, object shapes, ordering, and formatting for tokens the previous exporter produced. Allowed differences are Figma-authoritative **values**, the provenance comment (`Figma` instead of `Supernova`), and tokens that exist in Figma but were absent from the Supernova dump.
5. One brand per Figma file. `theme-light-on-brand` is a theme mode, not a brand. Other brands are later configuration, not forks of the pipeline.
6. Keep `exporters/tokens` until the next major release for parity and rollback. After Spirit parity, Figma writes committed output; Supernova is not the generator of record.

## Consequences

- Token delivery no longer depends on Supernova for the happy path. A Spirit Config snapshot generates the committed `packages/design-tokens/src/` tree. Allowed differences from the previous dump are the provenance comment (`Figma` vs `Supernova`), Figma-authoritative values, and tokens that exist in Figma but were never in the Supernova export.
- Authors run a development plugin in Figma desktop; there is no Marketplace distribution yet. The plugin may omit `file.key`; the repository config supplies it.
- The `Primitives` collection is alias source only and is not generated. Unused paint styles (avatars, patterns) are reported and omitted.
- Authors run a development plugin in Figma desktop; there is no Marketplace distribution yet.
- Malformed names, ambiguous scopes, missing aliases, and unmapped font families fail the export with aggregated diagnostics.
- Unused styles are reported and omitted. `figma-*` variables and typography styles containing `Link` or `Italic` stay excluded.
- Snapshot files must not be committed. Generated `js/` and `scss/` files remain the reviewable artifact.
